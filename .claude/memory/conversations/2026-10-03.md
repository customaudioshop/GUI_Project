## 🤖 Claude — 2026-10-03 22:31

Both projects already exist as fresh Godot 4.7 projects (`gui-builder` and `gui-player`), set up with the GL Compatibility renderer and a .NET section. That renderer is a good fit for the player, since it has to run on Android and iOS.

Here's how I understand the plan:

```
 GUI Builder (PC/Mac)                         GUI Player (PC/Mac/Android/iOS)
 ┌───────────────────────┐   package file   ┌───────────────────────────┐
 │ drag/drop editor      │ ───────────────▶ │ load package              │
 │ properties, events    │  layout + logic  │ build controls at runtime │
 │ asset import          │  + images/fonts  │ run the logic             │
 └───────────────────────┘                  └───────────────────────────┘
```

**The package format matters most.** Both apps depend on it, so I'd define it first:

- **Layout:** a JSON tree of nodes such as `Button`, `Label` and `Image`, each with its properties. It's readable, easy to version, and easy to check when the player loads it.
- **Assets:** images, fonts and sounds kept next to the layout. The whole thing gets zipped into one file, for example `.guipkg`.
- **Functions:** this is the riskiest choice, because of iOS:
  - **Visual events and actions** (for example, `on_click → go_to_page("settings")`): safest on every platform and on app stores, and easiest for non-programmers.
  - **GDScript in the package:** Godot can load it at runtime, even on iOS. But Apple's App Store rules on downloaded executable code could become a problem.
  - **C# in the package:** this won't work on iOS, because iOS builds compile C# ahead of time and can't load new code at runtime. C# is fine for writing the apps themselves, just not for code inside the package.

**Shared core:** keep the code that builds a GUI from a package in one shared folder that both projects use. The Builder's preview then runs the same code as the Player, so what you see in the editor is what users get.

A few questions before we start:

1. **Language:** GDScript or C# for the apps? The project has a .NET section, so did you plan on C#?
2. **Functions:** who writes them? Non-programmers using events and actions, programmers writing scripts, or both?
3. **Delivery:** how does the Player get packages? Opening a local file, downloading from a server, or bundled into the app?
4. **Use case:** what kind of GUIs are these? Kiosk screens, app prototypes, game menus, something else?

Once you answer, I can write a format spec and set up the shared core.

## 1. 가장 큰 제약: 플랫폼별 하드웨어 접근

Godot이 기본으로 지원하는 통신은 일부뿐이라 나머지는 네이티브 플러그인이 필요합니다.

| 프로토콜 | Godot 기본 지원 | PC/Mac | Android | iOS |
|---|---|---|---|---|
| TCP/UDP | ✅ 지원 | ✅ | ✅ | ✅ |
| DMX (Art-Net/sACN, 네트워크) | ✅ UDP로 직접 구현 가능 | ✅ | ✅ | ✅ |
| DMX (USB 인터페이스) | ❌ | 플러그인 | 플러그인 (USB OTG) | ❌ 사실상 불가 |
| MIDI | 입력만 지원 | 출력은 플러그인 | 플러그인 | 플러그인 (CoreMIDI) |
| UART (시리얼) | ❌ | 플러그인 | 플러그인 (USB OTG) | ❌ (MFi 인증 필요) |
| GPIO | ❌ | 전용 보드에서만 | ❌ | ❌ |
| IR 수신/송신 | ❌ | 외부 장치 필요 | 일부 폰만 송신 가능 | ❌ |

**결론:** 특히 iOS에서는 UART, GPIO, IR을 직접 다룰 수 없습니다. 그래서 다음 구조를 권장합니다.

```
 GUI Player (모든 플랫폼)
        │  TCP/UDP (네트워크로만 통신)
        ▼
 게이트웨이 장치 (Raspberry Pi / ESP32 등)
        │
        ├─ UART ─ 오디오 믹서
        ├─ GPIO ─ 릴레이
        ├─ IR   ─ 프로젝터/TV
        └─ DMX  ─ 조명
```

- **모바일 Player**는 네트워크(TCP/UDP, Art-Net, OSC)로만 통신합니다. 플랫폼 문제가 없습니다.
- **PC/Mac Player**는 직접 연결(USB 시리얼, MIDI 등)과 게이트웨이 경유를 모두 지원할 수 있습니다.
- Player 내부에는 **Transport 추상화 계층**을 두어, 위젯이 "어떤 장치에 무엇을 보낸다"만 알고 실제 전송 방식(직접/게이트웨이)은 몰라도 되게 만듭니다.

## 2. 패키지 포맷 개념 (초안)

장비 제어 GUI에 맞춰 다음 요소로 구성하는 것을 제안합니다.

- **devices**: 연결 정의 (예: `mixer1` = TCP 192.168.0.10:5000, `light1` = Art-Net universe 0)
- **pages / widgets**: 화면, 버튼, 페이더, 노브 등
- **actions**: 위젯 이벤트에 연결할 동작 (예: 페이더 움직임 → `mixer1`에 명령 전송)
- **bindings (양방향 피드백)**: 장치에서 받은 응답으로 UI를 갱신합니다. 예를 들어 믹서에서 볼륨을 바꾸면 화면의 페이더도 함께 움직입니다. 장비 제어 UI에서는 이 부분이 중요합니다.
- **assets**: 이미지, 폰트

## 스크립트 형식

```
# 페이더를 움직이면 믹서 볼륨과 조명 밝기를 함께 조절
set $level = round(scale($value, 0, 1, 0, 255))
send mixer1 "SET CH1 VOL $level\n"
dmx light1 1 ($level)

if $value > 0.5
    gpio relay 3 on
else
    gpio relay 3 off
end

repeat 3
    ir tv "power"
    wait 200
end
```

- 한 줄에 한 문장을 쓰고, `#`으로 주석을 답니다.
- 변수는 `$`로 시작하며, 텍스트 안에서도 `"VOL $level"`처럼 쓸 수 있습니다.
- 조건문은 `if`/`elif`/`else`/`end`, 반복문은 `repeat`/`end`입니다.
